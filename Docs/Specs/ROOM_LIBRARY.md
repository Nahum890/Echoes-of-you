# ROOM_LIBRARY.md — Technical Catalog & Schemas for 48 Room Modules
## Spec ID: SPEC-004
## Version: 4.0 (AI-Executable)

---

### 1. PURPOSE
Defines the complete technical catalog and executable datasheets for all 48 room variants (`ModuleType` indices 0 to 47) in *Echoes of You 2.0*. Specifies exact volumetric dimensions $[W, H, D]$, prop density ranges $[Min, Max]$, base URP light parameters, fog density $D_{fog}$, and required access alignments.

### 2. SCOPE
Applies to `EchoesModuleFactory.cs`, `EchoesNewProductionBuilder.cs`, and `LevelBlueprint` assets. Excludes prop mesh geometry definitions.

### 3. AUTHORITY
Nivel 3 (Especificación Ejecutable). Subordinate to `SOURCE_OF_TRUTH.md` (`SPEC-000`) and `ARCHITECTURE_GRAMMAR.md` (`SPEC-003`).

### 4. DEFINITIONS
- `ModuleType`: C# enum representing the structural template of a room (indices 0 to 47).
- `CustomData`: Key-value string configuration passed to `EchoesModuleFactory.cs` (syntax: `key1=val1;key2=val2`).
- `Fog Density ($D_{fog}$)`: Linear fog exponent value assigned to URP `RenderSettings.fogDensity`.

### 6. OUTPUTS
- Instantiated room GameObjects generated by `EchoesModuleFactory.cs`.
- Validation checks for `LevelValidator.cs`.

### 7. RULES

- `[RULE-ROM-001]`: **Module Dimension Enforcement**: Every instantiated room module MUST match the exact $[W, H, D]$ vector defined in Table 8.1. Tolerance $\pm 0.0\text{m}$.
- `[RULE-ROM-002]`: **Prop Count Bounds**: Instantiated prop count inside any room MUST satisfy $Min \le Count_{props} \le Max$.
- `[RULE-ROM-003]`: **Doorway Grid Alignment**: Entrance and exit doors MUST be snapped to the $3.0\text{m}$ grid with door height $H_{door} = 2.40\text{m}$.
- `[RULE-ROM-004]`: **CustomData Syntax**: The `customData` field MUST follow strict semicolon-separated key-value pairs (`key=value;key=value`).

### 9. CONSTRAINTS
- `[CONS-ROM-001]`: Prohibido instantiating `SchoolClassroom` without a blackboard and teacher desk.
- `[CONS-ROM-002]`: Prohibido overlap between two room module bounding volumes in 3D space.

### 10. VALIDATION
- `[VAL-ROM-001]`: `LevelValidator.cs` parses scene hierarchy and asserts prop counts fall within $[Min, Max]$ for each module.
- `[VAL-ROM-002]`: CustomData parser validates string syntax against key-value regex `^([a-zA-Z0-9_]+=[a-zA-Z0-9_.-]+;?)+$`.

### 11. EXAMPLES

#### Example 11.1: Valid Room Module Definition in C#
```csharp
ModulePlacement placement = new ModulePlacement
{
    moduleType = ModuleType.SchoolEntrance, // Index 47
    position = new Vector3(0, 0, 0),
    rotation = Quaternion.identity,
    customData = "doors=glass;arches=true"
};
GameObject room = EchoesModuleFactory.Instance.CreateModule(placement);
```

### 12. FAILURE CASES
- `[FAIL-ROM-001]`: **Invalid CustomData Syntax**: Result: Factory logs warning and uses default parameters.
- `[FAIL-ROM-002]`: **Prop Bounds Overflow**: Result: `LevelValidator` flags `FAIL-ROM-02`.
