## Spec ID: AUDIT-AUD-001
## Version: 1.0
## Date: 2026-08-15
## Audience: Game Audio Director, Unity Audio System Architect
## Authority: Audit document (read-only evidence base) — subordinate to `SOURCE_OF_TRUTH.md` `[SPEC-000]`

---

## 1. PURPOSE

Establishes an evidence-based diagnosis of the current state of the audio system in *Echoes of You 2.0* prior to the redesign described in `Docs/Specs/AUDIO_DIRECTION.md`. Enumerates existing assets, runtime behaviour, specification inconsistencies, violated rules, and soundless gameplay events.

## 2. SCOPE

Applies to:
- `Assets/Resources/EchoesAudioMixer.mixer`
- `Assets/Scripts/EchoesAudioManager.cs`
- `Assets/Editor/EchoesAudioMixerBuilder.cs`
- All runtime `AudioSource` components in C# scripts
- All audio clip assets present in `Assets/`
- Audio-related ExecutableSpec YAMLs under `Docs/ExecutableSpecs/audio/`

Excludes visual shader rendering and narrative script content.

## 3. METHODOLOGY

1. Inventory of on-disk audio assets (`.wav`, `.mp3`, `.aiff`, `.ogg`).
2. Static analysis of every C# script referencing `AudioSource`, `AudioMixer`, `PlayOneShot`, or `PlayClipAtPoint`.
3. Cross-check of the live AudioMixer asset against the four competing YAML schemas.
4. Mapping of declared gameplay hook points (`OnJumped`, `OnLanded`, `StartRecording`, etc.) to existing audio feedback.
5. Note: the Unity Editor had zero connected MCP instances during the audit, so in-editor runtime inspection of the mixer hierarchy was not possible; conclusions about the mixer are derived from the builder script `EchoesAudioMixerBuilder.cs` and the on-disk `.mixer` asset path.

## 4. AUDIO MIXER — CURRENT STATE

### 4.1 Asset
- Path: `Assets/Resources/EchoesAudioMixer.mixer`
- Generated by: `EchoesAudioMixerBuilder.cs` (`[InitializeOnLoad]`) via Reflection into `UnityEditor.Audio.AudioMixerController.CreateMixerControllerAtPath`.
- Failsafe: if `FindMatchingGroups("Master").Length == 0` the asset is deleted and regenerated.

### 4.2 Bus hierarchy actually produced by the builder

```
Master [exp: MasterVolume]
├─ Music [exp: MusicVolume]
├─ SFX   [exp: SFXVolume]
└─ Echo  [exp: EchoVolume]
```

Only **4 groups**. Only **4 exposed parameters**. No DSP effects, no snapshots, no ducking, no child sub-groups under SFX.

### 4.3 Spec / runtime divergence

Four different YAML schemas describe the bus layout, none of which match the builder:

| Source | Proposed buses | Match with runtime |
|---|---|---|
| `audio_architecture.yaml` (SPEC-EXEC-AUD-001) | `Master/BGM`, `Master/SFX/SFX_Player`, `SFX_Echo`, `SFX_Puzzle`, `Master/TapeHiss` | 0% |
| `audio_mixer_schema.yaml` (SPEC-127 exec) | `Master/BGM`, `Master/SFX/SFX_Player/SFX_Puzzle/SFX_Echo`, `Master/TapeHiss` | 0% |
| `audio_dsp_spec.yaml` | `Master/Music`, `Master/SFX/{Echo, Puzzle, UI, Foley}`, `Master/Ambience`, `Master/TapeHiss` | partial (Music, SFX, Echo present; Ambience/TapeHiss/UI/Foley absent) |
| `AUDIO_DSP_DUCKING_MATRIX.yaml` | references `Master/UI`, `Master/SFX/Player`, `Master/Ambient` | 0% — referenced buses do not exist |
| **Runtime (builder)** | `Master/Music/SFX/Echo` | ground truth |

### 4.4 Missing mixer features
- **No snapshots** — `AudioMixer.FindSnapshot` returns nothing. The ducking and music-state-transition model described in `AUDIO_MIXER_SCHEMA.md` (RULE-MIX-004) is therefore unimplementable in the current asset.
- **No bandpass DSP** — `RULE-AUD-001` (300 HP / 3500 LP on Echo + TapeHiss) cannot be satisfied. `EchoPlayback.cs` compensates per-source by adding `AudioLowPassFilter` + `AudioHighPassFilter` (`ApplyAnalogAudioFilters`), violating the mixer-centric DSP model.
- **No ducking sidechains** — `AUDIO_DSP_DUCKING_MATRIX.yaml` defines DUCK-001/002/003 but no bus carries a compressor effect configured against them.
- **No Ambience bus** — despite 8 ambience-related clips already on disk, no dedicated bus exists.
- **No Voice bus** — narrative dialogue AudioSources route to nothing.
- **No UI bus** — `MenuHoverSystem` UI AudioSource is ungrouped.

## 5. RUNTIME MANAGER — CURRENT STATE

### 5.1 `EchoesAudioManager.cs`
- Singleton with `DontDestroyOnLoad`. Provides 4 volume setters + PlayerPrefs persistence with log10→dB conversion. `EnsureExists()` factory. `FindGroup(name)` thin wrapper.
- **No API for**: event firing, snapshots, snapshot transitions, ducking, cooldowns, randomization, spatial-source pooling, music state machine, occlusion.
- `PlayFluorescentHum(position, intensity)` is a stub with no implementation.
- Volume defaults: Master 0.84 · Music 0.60 · SFX 0.72 · Echo 0.70.

### 5.2 Game-feel path: `GameFeelController.cs`
This is the *de facto* runtime audio dispatcher today:
- 1 SFX AudioSource + 3 ambient AudioSources.
- SFX source routed to `audioMgr.FindGroup("SFX")`.
- Ambient sources routed to `audioMgr.FindGroup("Music")` (**bug**: ambient room tones route to the Music bus, polluting music ducking).
- Exposes 16 clip slots via `[SerializeField] AudioClip` (jump, landing, hard landing, footstep, scrape, gravityShift, puzzleSolved, record, recordStop, echoSpawn, echoFade, softError, platePress, doorMove, playerDeath, respawn, ambientLoop, industrialDrone, ventilationHum, clockChime).
- Triggers: `PlayJump`, `PlayLanding`, `PlayFootstep`, `PlayEchoSpawn`, `PlayEchoFade`, `PlayPuzzleSolved`, etc. — invoked from gameplay scripts via `GameFeelController.Instance?....`.
- Spawns transient `AudioSource` GameObjects for one-shots (`SpawnEffect` helper), no pooling — risk of alloc churn.

### 5.3 `MenuHoverSystem.cs`
- Already implements UI feedback: `hoverIn`, `hoverOut`, `clickConfirm`, `navMove` with per-event pitch (1.0 / 0.85 / 1.1 / random 0.95–1.05).
- AudioSource is 2D, priority 64, but routes to default group (no UI bus).
- CRT ambient hum source present, faded in over 2s.

### 5.4 `EchoPlayback.cs` — RULE VIOLATIONS
`ConfigureSpatialVoicePlayback` produces the following values, all of which contradict `RULE-AUD-004` / `RULE-AUD-005` / `RULE-MIX-003`:
- `minDistance = 4f` (spec: 1.0)
- `maxDistance = 42f` (spec: 18.0)
- `dopplerLevel = 0.05f` (spec: 0.0)
- `spread = 18f` (spec: 0.0)
- `spatialBlend = 1f` (OK)
- `rolloffMode = Logarithmic` (OK)

### 5.5 `VN_DialogueController.cs`
- AudioSource present for voice playback. No `outputAudioMixerGroup` assignment — routes to Master directly. No DSP treatment for the cassette aesthetic.

### 5.6 `LightFlicker.cs`
- `GetComponent<AudioSource>()` for fluorescent hum. No mixer routing; no verified activation logic.

### 7.3 Entirely missing subsystems
- **Music state machine** — no `EXPLORATION / TENSION / PUZZLE / MEMORY / DIALOGUE / ENDING / SILENCE` states, no transition logic, no "no constant music" enforcement.
- **Mixer snapshots** — 0 snapshots defined.
- **Ducking** — DUCK-001/002/003 are YAML only.
- **Occlusion** — `AUDIO_SPATIALIZATION_SPEC.yaml` describes occlusion (800 Hz LP closed, 22 kHz open, lerp 4 s) but no `AudioListener` or per-source occlusion component implements it.
- **Voice management / virtualization** — `audio_dsp_spec.yaml` declares max_voices=32, priority=distance, virtualization=true. No `AudioConfiguration` or voice-limit logic exists in code.
- **TapeHiss constant bus** — `RULE-MIX-001` requires always-on TapeHiss at -18 dB. The bus does not exist; the hiss clip exists but is unused.
- **Bandpass on Echo bus** — `RULE-MIX-002` unsatisfied at the mixer level. Worked around per-source inside `EchoPlayback`.
- **Hardcoded volume prohibition** — `RULE-MIX-005` is violated: `EchoPlayback` does `source.volume = Mathf.Lerp(...)` directly during fade-out; `MenuHoverSystem` multiplies `volume` in `PlayOneShot`.

## 9. CONSTRAINTS ENCOUNTERED

- Zero live Unity instances (MCP `instances` returned `instance_count: 0`), so the `.mixer` asset could not be introspected at runtime; conclusions rest on `EchoesAudioMixerBuilder.cs` as source of truth for the asset's authored state.
- `EchoesAudioMixerBuilder.cs` uses Reflection against `UnityEditor.Audio.AudioMixerController` internal APIs. Extending the builder to add 9 groups + 9 snapshots + DSP must preserve this Reflection path.
- `EchoPlayback.cs` adds `AudioLowPassFilter` + `AudioHighPassFilter` per-source, and `RemoveVoiceDegradingFilters` removes them on Standard mode. Migrating DSP to the mixer risks removing per-source Standard/Analog discrimination unless the script routes to different sub-groups per mode.

## 11. RECOMMENDED ACTIONS

1. Rebuild `EchoesAudioMixer.mixer` with the canonical 9-group hierarchy and 7 musical + 2 overlay snapshots described in `AUDIO_DIRECTION.md`.
2. Introduce `AudioEventBus` + `AudioEventRegistry` (ScriptableObject) to decouple event firing from gameplay scripts.
3. Introduce `MusicStateMachine` driving `AudioMixer.TransitionToSnapshot` for emotional pacing; enforce "no constant music" by defaulting to `SILENCE`.
4. Migrate `EchoPlayback` spatial config to spec values (1m / 18m / doppler 0 / spread 0); move bandpass DSP to the `SFX_Echo` bus.
5. Create the missing buses (`Ambience`, `Voice`, `UI`, `Foley`, `TapeHiss`) on the mixer.
6. Add `Interaction Available/Confirm/Denied`, `Recording Warning`, `Puzzle Success/Failure`, `Dialogue Open/Advance`, `Pause Open/Close`, `Level Transition`, `Memory Discovery` — all currently silent gameplay moments.
7. Standardise clip asset paths under `Assets/Audio/{Category}/...` to match the YAML schemas; migrate the existing `Efectos de sonido/` clips as a non-breaking first pass with aliases.
8. Add mixer ducking via snapshots (decision approved) — no per-frame DSP sidechain.
